# 구현 결정 기록

기준일: 2026-10-23 (Asia/Seoul). 요구사항의 기준은 `PRODUCT_SPEC.md`의 한국어 설명과 저장소 `AGENTS.md`입니다.

## 1. 이번 범위: Phase 0·1

초기 저장소에는 콘텐츠, 검수 문서, 생성·검증 도구와 제품 명세가 있었습니다. 먼저 모바일 탐색부터 한 번의 완전한 퀘스트, 로컬 저장, 복습, 보상, 백업, 오프라인 실행까지 연결합니다. 진단·보스전·개인화·아바타를 동시에 구현하지 않습니다.

Phase 0·1의 **기능 구현과 실제 운영 수용 기준을 구분**합니다. 자동 검사를 통과하더라도, 미성년 학습자가 실제 iPhone에서 혼자 퀘스트를 완료하고 다음날 복습을 확인하기 전에는 제품 명세의 실기기 완료 조건을 달성했다고 보고하지 않습니다.

## 2. 승인 콘텐츠와 데모의 격리

- 원본 문제은행 전체는 `draft`로 유지합니다. 구조 검사로 `validated` 또는 `approved`로 승격하지 않습니다.
- 일반 학습 모드는 문항·상위 어휘/지문이 허용하는 `approved` 콘텐츠만 선택합니다. 현재 승인 항목이 0개이므로 학습 준비 안내를 표시합니다.
- `npm run dev`와 `npm run build:demo`에서만 설정의 **데모 콘텐츠 사용(검수 전)** 를 제공합니다. 명시적인 선택 전에는 데모를 실행하지 않습니다.
- `npm run build` 결과에는 데모 전환 기능을 제공하지 않습니다. 개발용 설정 값이 남아 있어도 일반 배포는 승인 콘텐츠만 출제합니다.
- 데모 선택은 주소의 `?demo=1`로 유지합니다. manifest 시작 주소는 `/`이므로 홈 화면 앱의 새 실행에서 다시 데모를 켜야 할 수 있습니다. 별도 데모 데이터베이스는 보존합니다.
- 데모와 일반 학습은 별도 IndexedDB 데이터베이스를 사용합니다. 데모 시도가 정식 학습 성장 기록에 섞이지 않게 합니다.
- 독해 질문의 승인 상태는 원본 규격에 따라 상위 지문으로부터 상속합니다. 질문별 검수 상태 도입은 후속 콘텐츠 관리 작업입니다.

이는 현재 승인된 문제가 없다는 사실을 숨기지 않으면서 개발·검수용 퀘스트를 확인하기 위한 결정입니다. 데모는 교육적 검수 완료를 의미하지 않습니다.

## 3. 12주 데이터와 시간 예산

기존 300단어·600어휘 질문·60구문·60지문·진단·계획·보스전의 ID와 내용은 보존합니다. 일일 계획의 기본값은 새 어휘 5개, 구문 1개, 독해 1지문/2문항입니다. SRS due 복습을 먼저 배치하고 권장 시간 예산에 맞게 새로운 콘텐츠를 줄입니다. 12분은 퀴즈 제한시간이 아닙니다.

최초 학습일에는 복습 이력이 없어 복습 단계가 비어 있을 수 있습니다. 쉬는 날은 감점이나 강제 따라잡기를 만들지 않습니다. 실제 소요시간·오답률에 기반한 고급 적응형 분량 조절은 Phase 2에서 검증합니다.

시간 예산으로 일일 계획의 어휘 카드 5개를 모두 끝내지 못한 구성은 `${plan.id}:partial`로 기록합니다. 이미 학습한 단어의 복습 상태를 확인하여 남은 새 단어를 다음 학습에 이어 붙이고, 다섯 단어를 모두 다룬 뒤 해당 계획을 완료 처리합니다. 수동 읽기 밴드 선택 시에는 원래 배정과 가까운 주차의 같은 밴드 지문으로 대체할 수 있습니다. 이는 원본 배정 자료를 변경하지 않는 세션 단위 선택입니다.

## 4. 저장·보상·숙련도

- 답변은 시도 이벤트로 저장하고, 보상 이벤트의 유일 키와 IndexedDB 트랜잭션으로 중복 지급을 방지합니다.
- 진행 세션에는 문항 순서와 현재 위치를 저장하여 새로고침으로 문제·정답 피드백·보상이 재생성되지 않게 합니다.
- 날짜는 기기의 로컬 날짜를 사용합니다. UTC 날짜를 일일 복습 경계로 사용하지 않습니다.
- 인식 정답, 무힌트 능동 회상, 문맥 정답을 구분합니다. 인식 퀴즈만으로 숙련 완료를 부여하지 않습니다.
- 어휘 카드 완료도 처음 학습한 기록으로 다음날 복습을 예약합니다. 카드를 읽은 사실 자체는 정답·능동 회상 성공·XP로 세지 않습니다.
- 백업은 데이터베이스 스키마·콘텐츠 버전을 포함하고, 전체 구조와 관계를 검사한 뒤 트랜잭션으로 복원합니다. 저장소 손실에 대한 영구 보존 약속은 하지 않습니다.

현재 어휘 객관식 원본은 뜻 인식 형식입니다. 검수된 문맥 적용 어휘 문항이 없으므로, 능동 회상 복습을 맞혀도 문맥 성공 요건이 채워지지 않으면 어휘 숙련을 완료로 표시하지 않습니다. 인식 문제를 문맥 문제로 이름만 바꾸거나 독해 정답을 임의로 어휘의 문맥 숙련 증거로 연결하지 않습니다.

자정을 넘겨 이전 세션의 어휘 카드를 이어서 학습한 경우 카드 예약일은 원래 세션 날짜 기준을 보존합니다. 이미 예약일이 지난 단어는 즉시 due가 될 수 있으며, 기록 없이 복습일을 늦추는 대신 보수적으로 다시 확인합니다. 실제 정답 시도에는 현재 로컬 날짜를 사용합니다.

## 5. PWA와 개인정보

개발 서버 기본 포트는 4175입니다. 현재 Windows 환경에서 5173 바인딩이 `EACCES`로 실패하여 실제 실행을 확인한 포트로 지정했습니다. 네트워크 주소는 같은 Wi-Fi의 iPhone 화면 확인에 사용하며, 오프라인 설치 시험은 HTTPS 경로로 별도 진행합니다.

정적 HTTPS 배포와 iPhone Safari의 홈 화면 설치를 대상으로 합니다. 네이티브 iOS 앱, 서버, 로그인, 광고, 분석 추적기, 클라우드 동기화, AI 호출은 추가하지 않습니다. 앱 코드와 콘텐츠는 서비스 워커로 캐시하고 학습 기록은 IndexedDB에 저장합니다. 최초 방문·설치는 온라인이어야 합니다.

일반 Wi-Fi HTTP 개발 접속은 화면 확인에 사용할 수 있지만 iPhone service worker의 증거로 인정하지 않습니다. Playwright WebKit 성공도 실제 iOS Safari·홈 화면 검증으로 보고하지 않습니다. 실제 기기 결과는 `IPHONE_TEST_CHECKLIST.md`에 별도로 기록합니다.

## 8. 모바일 학습 화면 개편 — 2026-10-23

사용자의 모바일 앱 중심 디자인 요청에 따라 파랑·초록 색상, 둥근 학습 버튼, 4단계 경로와 캐릭터 중심의 화면으로 개편했습니다. 모든 화면은 최대 480 CSS px의 한 열을 사용하고 넓은 화면에서도 중앙에 유지합니다. 홈에는 오늘의 단원·진행 경로·대표 시작 버튼을 배치합니다. 학습 중에는 진행률, 한 문항과 제출·다음 버튼에 집중하도록 상단 앱 헤더와 하단 탐색을 숨깁니다.

루미(하늘 여우), 모모(민트 고양이), 노바(별빛 토끼)는 로컬 SVG로 직접 제작했습니다. 외부 이미지·폰트 요청 없이 홈, 문제 피드백과 완료 화면에 선택한 친구를 사용합니다. 친구 3종 선택은 이번 단계에 포함하며, 보상으로 의상이나 아이템을 얻는 꾸미기는 후속 범위입니다.

설정에 선택적 `avatarId: 'lumi' | 'momo' | 'nova'`를 추가했습니다. 기존 설정·백업에 필드가 없으면 루미를 표시하므로 이전 스키마 1 백업과 호환됩니다. 선택한 값은 현재 모드의 IndexedDB 설정에 저장하고 백업에도 포함합니다.

브라우저 검증은 375·430 CSS px 모바일 화면과 1440 CSS px 화면의 중앙 정렬, 가로 넘침, 주요 버튼 44px 이상, 학습 중 탐색 숨김, 아바타 선택 유지·복원, 기존 퀘스트와 오프라인 동작을 확인합니다. 입력 화면의 375×460 축소 viewport 검사는 실제 iPhone 키보드 검증과 구분합니다. 실기기 Safari·홈 화면·VoiceOver 확인은 계속 미실시이며 결과는 `MOBILE_REDESIGN_REPORT.md`와 별도 실기기 체크리스트에 기록합니다.

## 9. 시몬치치 이름과 기본 친구 변경 — 2026-10-23

사용자 요청에 따라 표시 이름을 **시몬치치**로 바꿨습니다. 앱 로고, 브라우저 제목, 설치용 manifest 이름, 설정 버전 표시와 새 백업 파일명에 적용합니다. 기본 친구 **몬치치**는 사용자가 제공한 참고 이미지의 황금빛 털과 검은 후드를 반영한 로컬 SVG로 표현하고 PWA 아이콘에도 사용합니다. 외부 이미지 요청이나 실행 시 이미지 생성 의존성은 추가하지 않습니다.

이 결정은 8절의 기본 친구 선택을 대체합니다. 신규 설정은 `avatarId: 'monchichi'`를 사용합니다. 기존 스키마 1 백업의 필드 누락과 `'lumi'` 값은 계속 수용하며 화면에서는 몬치치로 해석합니다. `'momo'`·`'nova'` 선택은 유지합니다. 기존 데이터베이스 이름, 콘텐츠 ID, 백업 스키마와 보상 기록 형식은 유지하여 이름 변경으로 학습 이력이 분리되지 않게 합니다.

몬치치·모모·노바의 선택 저장과 복원, 기존 퀘스트, 일반 빌드의 초안 차단은 브랜딩 변경 후 다시 검사합니다. 실행 결과와 화면은 `SIMONCHICHI_BRANDING_REPORT.md`에 기록하며 실제 iPhone 검증은 별도로 남깁니다.

## 10. 사용자가 요청한 Android 오프라인 APK — 2026-10-23

초기 iPhone PWA 범위에 사용자가 별도로 요청한 Android 설치형 체험을 추가했습니다. 기존 React 학습 화면을 Capacitor 8.5.3 Android 앱으로 감싸고 `dist-android`의 화면·아이콘·문제은행을 APK에 포함합니다. `server.url`과 원격 업데이트 서버를 사용하지 않습니다. 설치 후 PC 다운로드 서버가 없어도 실행하는 구조이며, Android에서는 서비스 워커를 등록하지 않습니다. iPhone은 기존 PWA를 유지하며 네이티브 iOS 앱을 추가하지 않습니다.

개인 체험용 디버그 서명 APK의 앱 이름은 **시몬치치**, application ID는 `com.simonchichi.app`, 버전은 `0.1.0`/versionCode 1입니다. Android 최소 API 24·대상 API 36으로 빌드합니다. 스토어용 릴리스 서명과 배포는 이번 범위에 포함하지 않습니다.

APK도 처음에는 일반 학습 모드로 실행합니다. 초안 콘텐츠 사용은 설정에서 직접 켜야 하며 네이티브 Preferences에는 이 모드 선택만 저장합니다. 학습 기록·설정·보상은 기존 Dexie 구조를 유지합니다. 앱과 브라우저 저장소는 분리되어 있으므로 이전 웹 기록은 같은 콘텐츠 버전·모드의 JSON 백업으로 가져옵니다. 일반 웹 배포의 승인 콘텐츠 제한도 유지합니다.

## 21. GitHub Pages의 루트·프로젝트 경로 배포 준비 (2026-11-01)

사용자의 GitHub Pages 게시 요청에 따라 정적 웹 배포 경로와 공식 Actions 워크플로를 준비합니다. `configure-pages`의 `base_path`를 `VITE_BASE_PATH`로 전달해 계정 사이트 `/`와 프로젝트 사이트 `/저장소명/`를 처리합니다. manifest 시작 주소·scope·아이콘, service worker, 사전 라이선스 링크가 같은 경로를 따릅니다. Android는 기존 로컬 루트를 유지하며 학습·보상·저장소 스키마를 변경하지 않습니다.

워크플로는 고정한 공식 액션과 Node.js 24에서 잠금 파일 설치, 타입·린트·단위·콘텐츠 검사, 웹 빌드를 실행한 뒤 `dist/`만 업로드합니다. 소스 읽기 job과 Pages/OIDC 쓰기 job의 권한을 나누며 실패한 빌드나 다른 브랜치를 배포하지 않습니다. APK 빌드와 Pages 자동 활성화는 하지 않습니다.

원본 PDF·개인 백업·검사 스냅샷·개발 도구·서명 자료는 공개 저장소 및 사이트에 섞지 않습니다. 빌드가 요구하는 생성 콘텐츠와 출처 문서, 합성 검사 fixture는 구별하여 관리합니다. `.gitignore`는 추적되지 않은 파일을 보호하는 규칙일 뿐 이미 올라간 파일을 회수하는 기능이 아닙니다.

일반 Pages 사이트는 공개이며, 저장소가 비공개여도 방문자의 접근 제한을 자동 보장하지 않습니다. 앱 번들에 포함된 단어·지문·그림의 인터넷 공개 범위를 별도로 확정하고 출처·라이선스를 유지합니다. 학습 기록은 여전히 기기 저장소에 남으며 다른 origin이나 Android에서 새 웹 주소로 자동 동기화하지 않습니다. 필요한 이전은 검증된 JSON 백업·복원으로 수행합니다.

로컬 프로젝트 경로 Chromium/WebKit 4건과 기본 루트 2건은 통과했습니다. 실제 GitHub Actions 배포·공개 URL 동작과 실제 iPhone 홈 화면 확인은 별도 단계이며 완료했다고 주장하지 않습니다. 설정 방법과 검증 범위는 [GitHub Pages 안내](GITHUB_PAGES.md)에 기록합니다.

## 22. 게시 중단 뒤 PWA 실행과 기록 보존의 조건 (2026-11-01)

사용자가 제시한 ‘공개 상태에서 설치한 뒤 비공개로 전환하고, 업데이트 때만 다시 공개’라는 운영 방식을 검토합니다. 정상 설치한 service worker와 사전 캐시가 남아 있으면 서버가 온라인 404를 반환하더라도 기존 앱을 실행할 수 있습니다. 현재 Workbox 사전 캐시는 이미 cache-first이므로 모든 온라인 요청을 새로 가로채거나 404 페이지를 앱 캐시에 넣는 방식으로 변경하지 않습니다. 최초 설치·캐시 누락·worker 부재·저장소 정리는 별개 조건입니다.

필요한 코드 수정은 이미 설치된 웹 앱의 오프라인 준비 표시 복구로 한정합니다. 첫 설치 콜백만 기다리지 않고 현재 경로의 활성 worker와 시작 문서·현재 해시의 기본 자산 캐시를 읽어 상태를 확인합니다. 새 등록/업데이트가 404여도 기존 저장 상태를 확인할 수 있게 하되 다른 scope·오래된 해시·누락·읽기 오류에는 준비 완료를 표시하지 않습니다. 읽기 검사에서 기록을 바꾸거나 캐시를 제거하지 않으며 Android의 번들 실행 경로는 유지합니다.

GitHub Free의 저장소 비공개 전환은 Pages를 게시 중단시키지만 모든 요금제에서 같은 효과라고 일반화하지 않습니다. 재공개만으로 즉시 복구되거나 설치 기기에 새 버전이 전달된다고 약속하지 않고 Pages 설정·배포 성공·기기 업데이트 적용을 따로 확인합니다. 공개됐던 소스·번들·fork를 나중에 비공개 전환으로 회수했다고 주장하지 않습니다.

앱 파일 캐시와 학습 기록 IndexedDB를 구분합니다. 동일 origin과 데이터 스키마 호환성은 기록 재사용에 필요하지만 영구 보존을 보장하지 않습니다. WebKit 저장 공간 정리나 사용자의 데이터 삭제, 다른 origin·기기 이동에 대비해 JSON 백업을 유지합니다. 홈 화면 앱에 Safari의 일반적인 ‘7일’ 설명을 그대로 적용하거나 반대로 모든 삭제에서 면제된다고 표현하지 않습니다.

이번 요청은 운영 주장 검토와 필요한 로컬 수정·검사 범위입니다. 저장소의 public/private 변경, Pages 게시 중단·재게시를 실행하도록 승인한 것으로 해석하지 않습니다. 실제 iPhone 홈 화면의 장기 보존을 검증했다고 보고하지 않으며, 공식 근거·검사 범위와 운영 절차는 [GitHub Pages 안내](GITHUB_PAGES.md)에 기록합니다.

로컬 Chromium/WebKit에서는 온라인 상태의 실제 서버 404 뒤 정상 캐시로 새 페이지 실행·기존 10 XP/답변·백업 유지, `sw.js` 업데이트 실패 뒤 기존 활성 worker 유지, 준비 상태 표시 복구를 확인했습니다. 설치하지 않은 빈 브라우저는 같은 서버에서 404로 열리지 않았습니다. 최종 타입·린트·전체 단위 201건(15파일), 준비 상태 관련 단위 28건, 이 두 신규 검사를 포함한 프로젝트 경로 6건과 기본 루트 2건이 통과했습니다. 결과를 영구 설치 또는 실물 iPhone 통과로 확대하지 않습니다.

## 23. 오늘의 오답 버튼과 두 번 정답으로 해제하는 오답노트 (2026-11-02, 0.12.0)

기존 오늘 화면의 ‘오답 다시 도전’은 클릭 동작이 없는 루틴 안내 행이었고, 실제 재시험은 회차의 마지막 독해 이후에만 나타났습니다. 사용자가 누를 수 있는 버튼으로 바꾸어 별도 오답노트로 연결합니다. 기존 ‘복습함’ 명칭은 유지하고, 사용자가 요청한 학습 공간의 오답 목록·전용 퀴즈를 그 안에서 제공합니다.

단어는 canonical 어휘 ID로, 구문과 독해는 질문 ID로 오답을 묶습니다. 최근 오답 뒤 서로 다른 세션에서 정답을 두 번 저장하면 해제하며, 새 오답은 횟수를 0으로 초기화합니다. 같은 세션에서 같은 항목을 여러 번 맞혀도 한 번만 기여합니다. 마지막 재시험·기존 즉시 재도전 정답과 힌트 정답도 이 횟수에는 기여할 수 있지만, 무힌트 회상 숙련이나 기존 SRS 판정을 바꾸지는 않습니다. 답변 이력에서 계산하므로 목록 해제는 기록 삭제가 아닙니다.

전용 세션은 `sessionKind: 'mistakes'`로, 선택한 책과 관계없이 전체 미해결 오답의 최근 순서에서 최대 10문항을 고릅니다. 10개 미만도 실행하고 선택 결과·현재 위치를 저장합니다. 화면 필터·검색은 탐색용이며 퀴즈의 전체 모집단을 바꾸지 않습니다. 원래 정답·보기·독해 근거를 재사용하고 즉시 재도전과 추가 XP·완료 보너스는 제공하지 않습니다. 기존 과정의 29~49단계·한 번의 마지막 재시험·기존 복습 보상은 그대로입니다. 다른 퀴즈에서 오답이 해제되어도 이미 고정한 회차 재시험은 줄이거나 다시 뽑지 않습니다.

Dexie 3의 여섯 테이블·DB 이름·백업 6·기존 ID를 유지합니다. 과거 1~5 형식에 새로운 전용 세션을 숨긴 파일은 거절하고, 정상 과거 기록의 답변·보상·진도·구매·장착은 보존합니다. 업데이트는 iPhone의 같은 origin/홈 화면 앱에서, Android의 같은 앱 ID/서명으로 덮어 설치하며 기록 초기화·앱 삭제를 요구하지 않습니다. 다른 origin이나 기기로 이동할 때는 JSON 백업·복원을 사용하고 실제 휴대폰 검증 여부는 자동 검사와 구분합니다.

최종 타입·린트와 전체 단위 218개가 통과했습니다. 새 오답 6개·기존 test-first 4개, Pages 6개·기본 루트 2개로 대상 웹 18개를 확인했고, Android 에뮬레이터의 실제 0.11→0.12 업데이트는 제한된 기록 보존·미응답 퀴즈 재개 4개를 통과했습니다. 전체 결과와 실물 기기 미검증 범위는 [0.12.0 보고서](MISTAKES_REPORT.md)에 기록합니다.
